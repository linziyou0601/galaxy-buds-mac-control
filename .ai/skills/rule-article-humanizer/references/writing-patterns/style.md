# 風格

版面與標點層級的痕跡。判準以 Skill `/rule-documentation` 為準，本條目說明這些符號在腔調上的成因。

## 破折號

### 判準

全文沒有 `—`、`–`，也沒有當破折號用的 `--`。依 DOC-FMT-04，連字一律使用 ASCII `-`。

### 成因

破折號是 AI 產生的文字最可靠的痕跡之一。敘事段落常用它模仿行銷文案的停頓節奏。替換順序：句號（另起一句）、逗號（緊密的插入語）、冒號（引出說明）、括號（真正的插入語），或整句重組。

### 改寫前

```text
這個設定主要給管理員使用——一般使用者看不到——但它會影響所有人的報表。
```

### 改寫後

```text
這個設定只有管理員看得到，它會影響所有人的報表。
```

## 分號與換行

### 判準

依 DOC-FMT-05：同一件事的短句用「，」串接，主題轉換或各自獨立的陳述用「。」，結構對稱、分句內已有逗號的並列句與表格 cell 的並列項目才用「；」，並列的詞語用「、」。英文依英文標點習慣。

### 成因

模型常用「；」把兩個沒有關係的陳述黏在一起，製造正式感。同樣的習慣也會表現成用換行取代句號，讓兩個獨立陳述看起來像條列。反方向的失誤是把真正的並列句也拆成獨立短句，見 [technical-style](technical-style.md) 的「同一件事拆成多句」。

### 改寫前

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例；規格文件也進入補寫的高峰期。
```

### 改寫後

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例。規格文件也進入補寫的高峰期。
```

### 改寫前（換行變體）

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例
規格文件也進入補寫的高峰期
```

### 改寫後（換行變體）

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例。規格文件也進入補寫的高峰期。
```

## 粗體

### 判準

依 DOC-BOLD-01 與 DOC-BOLD-02，粗體只用於標籤位置。

### 成因

模型會把句中的專有名詞或縮寫加粗，讀者的視線被拉到不重要的地方。

### 改寫前

```text
它整合了 **OKR（目標與關鍵成果）**、**KPI（關鍵績效指標）**，以及 **平衡計分卡（BSC）**。
```

### 改寫後

```text
它整合了 OKR、KPI 與平衡計分卡。
```

## 粗體標籤條列

### 成因

模型把一段敘事拆成「**標籤**：說明」的條列，每項都是同樣的句型。欄位定義、設定項目這類結構化資料適合條列；敘事內容寫成段落。

### 改寫前

```text
- **使用者體驗**：透過新介面大幅改善使用者體驗。
- **效能**：透過最佳化演算法提升效能。
- **安全性**：透過端對端加密強化安全性。
```

### 改寫後

```text
這次更新換了新介面，查詢改用索引後快了一倍，傳輸也加上端對端加密。
```

## 表情符號

### 成因

模型在標題或條列前加表情符號，製造活潑感。產品介面本身使用的圖示，以及報告模板規定的狀態符號（例如 ✅、🚧），依模板保留。

### 改寫前

```text
🚀 **啟動階段**：產品於第三季上市
💡 **關鍵洞見**：使用者偏好簡單
```

### 改寫後

```text
產品於第三季上市。使用者研究顯示，大家偏好步驟少的設計。
```

## 引號一致

### 判準

中文引號一律使用「」，英文引號依英文習慣使用 `"`，同一份文件不混用彎引號與直引號。

### 成因

聊天介面多半預設輸出彎引號，貼進文件後與既有的「」混在一起。

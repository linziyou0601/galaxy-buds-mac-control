# 寫作模式型錄

Skill `/rule-article-humanizer` 的模式索引。每個條目檔收錄偵測訊號、成因與改寫前後對照。「改寫後」的文字同時符合所有其他條目，可以直接當成寫法參考。

## 條目索引

技術文字先查技術文體，再查語言與語法、填充與修辭腔、中文空話詞、交流殘留與風格。敘事段落從內容模式查起，全部條目都適用。

| 條目 | 檔案 | 涵蓋模式 | 主要對象 |
|---|---|---|---|
| 技術文體 | [technical-style](writing-patterns/technical-style.md) | 否定補述、名詞片段、翻譯腔、簡中與繁中用語、同一件事拆成多句 | 技術文字 |
| 語言與語法 | [language-grammar](writing-patterns/language-grammar.md) | AI 高頻詞、修飾語堆疊、迴避「是」、硬湊三項、同義詞輪換、虛假範圍、無主語片段 | 全部 |
| 填充與修辭腔 | [filler-rhetoric](writing-patterns/filler-rhetoric.md) | 填充短語、只描述清單長度的數字、疊加保留語、樂觀結論、權威腔、宣告式開場、破碎標題、以差異為錨點、人造金句、格言公式、口語修辭開場 | 全部 |
| 中文空話詞 | [zh-buzzword](writing-patterns/zh-buzzword.md) | 以抽象詞或比喻單字動詞取代具體動作的中文技術圈慣用詞 | 全部 |
| 交流殘留 | [communication](writing-patterns/communication.md) | 聊天回覆殘留、知識截止免責與臆測填空、諂媚語氣 | 全部 |
| 風格 | [style](writing-patterns/style.md) | 破折號、分號與換行、粗體、粗體標籤條列、表情符號、引號一致 | 全部 |
| 內容模式 | [content](writing-patterns/content.md) | 意義渲染、句尾偽分析、宣傳語、模糊歸因、挑戰與展望段落 | 敘事段落 |
| 完整範例 | [full-example](writing-patterns/full-example.md) | 一篇敘事文章從草稿、覆核到定稿 | 敘事段落 |

## 判斷是否為 AI 痕跡

改寫前先判斷這段文字是否真的有 AI 痕跡。判斷看模式群聚：單獨一個破折號、一個「此外」或一句短句都沒有意義，破折號加上硬湊三項、宣傳形容詞與公式化結論的組合，才是明確訊號。

下列特徵單獨出現時，不足以判定為 AI 痕跡：

| 特徵 | 理由 |
|---|---|
| 語法完美、風格一致 | 專業寫手與經過編輯的文章本來就是這樣 |
| 口語與正式語氣混雜 | 技術背景的作者常這樣寫 |
| 平淡、乾燥的敘述 | AI 痕跡有特定形態，乾燥只是一種寫法 |
| 正式或學術詞彙 | AI 過度使用的是語言與語法條目列出的特定詞，專業詞彙本身是正常用語 |
| 書信體開頭或結尾 | 問候語與署名是正常的書信慣例 |
| 單獨一個連接詞 | 「然而」「因此」堆疊出現時才是訊號 |
| 單獨一句短句 | 人也會用短句強調重點，連續堆疊才是斷奏腔 |
| 沒有附來源 | 多數內容本來就沒有引用 |
| 複雜而正確的排版 | 範本與編輯器本來就能產出乾淨版面 |
| 引用或範例中的模式詞 | 被討論的詞是對象，維持原樣 |

下列訊號代表真人寫作，改寫時保留：

- **具體、罕見、難以捏造的細節**：一個真實的錯誤代碼、一段奇怪的 log、「那位剛好在我牙醫樓上執業的律師」。
- **矛盾情緒與未解的張力**：「整體是好的，但它讓我有點不安，我說不清為什麼。」
- **帶時代印記的用語**：特定年份、特定團隊才懂的說法。
- **作者能解釋的用字選擇**：作者說得出「為什麼用這個詞」。
- **句長變化豐富**：長短句交錯。
- **插話、括號旁白與自我修正**：「（我一直想寫『幾乎』，但這件事其實是確定的。）」

## 型錄紀律

- 「改寫後」的範例符合所有條目，新增或修改範例時逐條自查。
- 範例使用通用情境，模組、服務與路徑以一般名稱描述。
- 新增模式時先建條目內容，再更新本索引與 SKILL.md 審查掛鉤的條目編號。
- 版面與標點的判準以 Skill `/rule-documentation` 為準，條目只說明腔調上的成因。

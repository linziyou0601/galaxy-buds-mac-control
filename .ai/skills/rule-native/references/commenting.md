# Swift 註解規範

註解讓維護者從目前檔案理解責任、資料來源、狀態變化、副作用、邊界條件與產出流向。

## 內容層次

先說明成員是什麼。理由會影響呼叫方式時補上 why，呼叫順序、空值、單位或失敗邊界會影響使用時補上 how。型別與欄位描述自身語意，演算法和資料轉換寫在實作位置。

## 文件註解

- 型別用 `///` 說明領域責任。
- 方法說明狀態副作用、參數語意、有效範圍、回傳值與失敗邊界。
- 數值欄位說明單位與索引基準，optional 說明 nil 的語意。
- 單行委派與 computed property 在語意不直覺時仍需說明。
- 外部協定的位元組 offset、位元遮罩與反向布林值說明依據。

## 行內與區段

逐一檢查每三行連續程式碼，判斷該區段前是否需要說明。宣告清單、同一原生版面與連續欄位可共用完整意圖說明，註解密度依資料流與判斷邊界決定。

每個 if、guard、switch、case、else 與 catch 分支都說明判斷原因、有效資料條件或回復行為，包含 closure 內的分支。分支說明可位於入口前或分支內首行，else 與 catch 的說明放在自身內容的首行，避免出現在上一個分支尾端。

每個完整意圖區塊前說明資料來源、判定理由、轉換目的或下一個接收者。外部呼叫、非同步取消、狀態變更、封包解析與錯誤回復是必要註解邊界。省略逐行翻譯語法的旁白。

同層責任群使用一致的 `// MARK: - 名稱`，方法內的局部意圖使用一般 `//`。註解描述終態行為，避免任務編號、編輯歷程與未驗證的硬體宣稱。

## 測試敘述

測試名稱描述觸發條件和結果。前置條件、執行與斷言用正體中文說明有意義的領域條件，失敗訊息要能定位輸入與邊界。

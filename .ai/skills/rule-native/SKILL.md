# 原生 App 程式撰寫規則

## 目的

維護 Buds Control 的原生元件、狀態責任、系統邊界與一致的 Swift 程式骨架。

## 適用範圍

Sources、Tests、機型 JSON、建置與驗證腳本。新增宣告、抽象及相依同時依 rule-minimalism，使用者可見文字與註解同時依 rule-article-humanizer。

## 技術與分層

- 使用 Swift、SwiftUI、AppKit、IOBluetooth、CoreBluetooth、CoreAudio、Observation 與 Foundation。
- App 管理程序與視窗生命週期，Bluetooth 管理連線與命令，Audio 管理系統輸出，Models 保存配置及狀態，Views 組合畫面。
- View 經服務操作外部裝置，解析器與配置驗證使用 Foundation，可獨立測試。
- 純轉換與固定資料採 struct 或 enum，系統 callback、共享參照狀態及資源生命週期採 class。
- 重用優先使用既有元件與服務組合，框架要求的 NSObject delegate 保留原生繼承。
- 同一責任維持同一服務邊界，拆檔與新增型別需有實際職責或呼叫點依據。

## 命名與風格

- Swift 型別與檔案使用 PascalCase，方法、屬性與參數使用 lowerCamelCase。
- 宣告按常數、相依、狀態、衍生狀態、初始化、生命週期及功能流程排列。
- 服務的啟動、觀察、連線、取消與釋放放在生命週期區，UI 的 body 與各畫面區段依閱讀順序排列。
- 同一欄位家族與支援方法保持鄰近，新增內容回到所屬區段。
- 大型流程使用對稱的 `// MARK: - 名稱`，同一分組先入口、後支援方法。
- 跨檔共用領域型別放在 Models，單一畫面使用的型別留在該畫面檔案。
- 不以壓單行、刪大括號或複雜巢狀三元運算壓縮必要流程。

## 型別與狀態

- 有限選項使用 enum，固定欄位資料使用具名 struct，執行期鍵對照才使用 Dictionary。
- 以 optional 表達未回報或未知值，數值欄位說明單位、索引與有效範圍。
- 外部資料通過長度、範圍、列舉與配置驗證後，才更新快照。
- MainActor 管理可觀察狀態，背景 callback 先複製資料，再切回 MainActor。
- 傳輸成功、耳機 ACK、狀態回報及實機效果各自判讀。
- 候選顯示值保持可見回饋，錯誤與未知值保留真實語意。

## 原生 UI 與元件

- 先查公開系統元件、SDK 宣告及既有 View，最後才建立必要的組合。
- 系統屬性可表達形狀、焦點或材質時直接使用，避免外套樣式破壞控件原生行為。
- 使用 NavigationSplitView、Form、Section、Button、Toggle、Picker、Slider、LabeledContent、NSPopover 與 NSWindow。
- 玻璃材質使用公開 Liquid Glass API，圓角、陰影、焦點、明暗與高對比由系統處理。
- 相同模式控制、ANC、圖片及設定列共用元件。
- 功能分類依 DESIGN，詳細頁避免重複設定責任，快捷控制經相同服務操作。
- 版面尺寸由產品組合需求決定，系統控制項採語意字級及原生樣式。
- 同時檢查快捷面板、詳細頁、啟用與未啟用視窗，編譯成功須搭配實際 UI 驗證。

## 配置與相容性

- 機型能力、服務 UUID、數值範圍、後段欄位、配色與素材由 JSON 載入。
- 穩定命令 ID、位元語意與共用協定以型別表達，機型差異留在配置。
- 配置於載入邊界驗證，未知 schema、無效欄位或不支援格式有明確失敗路徑。
- 相容性根據裝置能力、協定與實際回報，禁止依特定使用者、手機型號、手機版本或位址繞過流程。
- 新格式需有解析與測試，研究資料留在本機驗證產物。

## 系統服務與生命週期

- 每個 Task、Timer、notification、channel 與 listener 都有擁有者與停止邊界。
- 取消、重試與重連清除過期 buffer、快照及 pending 狀態，非同步結果依世代判斷是否有效。
- 外部輸入 callback 只做資料交接，避免同步等待 MainActor。
- 音量變更通知只更新數值，輸出或聲道變更才調整 CoreAudio 監聽。
- 快速連續操作需處理合併、重入與過期結果，維持可見狀態及原始聲道比例。
- 預覽使用示範資料，藍牙、系統音量與登入項目副作用保持停用。

## i18n 與資源

- 可見文字使用原生翻譯資源，正體中文與英文同步維護。
- 配置中的動態文字鍵也需驗證，權限文案保存在 InfoPlist.strings。
- 圖片依機型配置選擇，原檔、來源、使用條件及 SHA-256 保持一致。
- 真實診斷及序號留在本機，分享前檢查內容。

## 註解

依 [Swift 註解規範](references/commenting.md) 說明型別責任、資料來源、參數、單位、副作用、失敗與取消邊界。區段說明完整意圖，註解描述終態行為。

## 驗證

- 執行格式檢查、腳本語法檢查、核心測試、資源檢查及 App 建置。
- 非平凡邏輯保留能在行為損壞時失敗的最小測試。
- 純排版以實際介面驗收，系統服務與協定以相關裝置或系統驗證。
- 藍牙功能分別記錄兩款耳機型號、韌體、操作、回報與未驗證範圍。
- 完成後逐檔盤查新宣告、呼叫點、分層、命名、註解與相依，清除不成立的實體。

## 設計說明

涉及跨層、非同步、狀態、系統服務、共用元件或新相依時，先以簡短文字說明變更、理由及受影響的既有流程。一般可逆工作依使用者授權繼續，不把設計說明當成額外核准流程。

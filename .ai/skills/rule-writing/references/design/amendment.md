# 規則修改流程

新增、修改或刪除一條規則時依本檔前進：先寫條目，再寫進機讀定義表，以標準答案集與語料量測確認結果，最後依量測決定層級。

## 修改步驟

一條規則從條目檔開始，依序寫到機讀定義表與標準答案集。刪除規則時反向進行：先刪表內的列與標準答案集的例子，再刪條目索引的列與條目檔的標題。新增或修改的步驟：

1. 在 `references/writing/` 對應組的條目檔為條目新增一個標題，寫判準、偵測訊號、成因與改寫前後對照。
2. 條目編號登記在 `rule-index.tsv`，參照寫成「檔案#標題」，指向上一步的標題。
3. 規則寫進 `check-rules.tsv`：預設層級、範圍、說明、判定問題與改法。判定問題寫成違規的情況，答案「是」表示違規。
4. 偵測寫進對應的表：寫得成正規式的寫進 `check-patterns.tsv`，一組詞寫進 `lex-avoid.tsv` 並在規則表寫成群門檻，成對的詞寫進 `check-pairs.tsv`。這三種都寫不成時才由程式判定，程式裡只寫規則名稱，並加進該檢查模組匯出的 `RULES`。
5. 在 `scripts/cases/` 加上會命中與不會命中的例子，更新 `expected.tsv`。
6. 依下一節量測語料，決定預設層級與各文風的覆寫。
7. 執行回歸量測，全部通過才交付。

## 依語料決定層級

新規則或改過條件的規則，在下列語料上執行 lint，統計命中數，再逐筆抽樣讀上下文，估計誤報的比例：

- 根目錄的 `AGENTS.md` 與 `README.md`
- 專案既有文件與筆記
- skill 的主文與參考文件

依誤報的比例與命中數決定層級。誤報集中在幾個詞時，先加例外或邊界詞縮小條件，再重新量測，例如「代碼」在台灣是一般用法，從技術用語對照的比對中移除，「時間戳記」的「時間戳」以邊界詞排除：

| 量測結果 | 層級 |
|---|---|
| 抽樣沒有誤報，而且改法是一對一的取代 | 錯誤 |
| 多數是違規，誤報有明確的形態 | 警告，把誤報的形態寫進判定問題或例外欄 |
| 多數是合理的寫法 | 提示 |
| 某一類文件幾乎全是合理的寫法 | 在該文風的覆寫表降級或關閉 |

## 回歸量測

修改機讀定義表或引擎後，依序確認：

- `node scripts/lint.mjs --cases scripts/cases --project scripts/cases/tables` 全部通過。
- `node scripts/lint.mjs . --root {儲存庫根目錄} --project {專案定義表目錄}` 在 skill 目錄下沒有發現項目，條目檔的範例符合全部條目。
- 上一節的語料修改前後各執行一次 `--json`，逐筆比對差異，每一筆差異都要找得到修改的原因。

# 機讀定義表型錄

`references/tables/` 是 `scripts/lint.mjs` 讀取的機讀定義表，人與 lint 讀同一份資料。lint 實作通用機制，規則的層級、判定問題、改法、詞、正規式、成對連接詞、門檻、文風、路徑設定與 markdown 寫法都寫在這裡，改規則就是改表。各規則對應的條目與判法寫在 [writing-catalog](writing-catalog.md) 的條目檔。

## 分組

每張表回答一個問題，檔名依「類別-對象.tsv」命名，前綴是表的類別：`rule-` 是條目索引，`check-` 是判定與回報，`lex-` 是詞與寫法，`layout-` 是版面與套用的檔案。規則表是中心：正規式表、詞表與門檻表的「規則」欄指向規則表的規則名稱，規則表的條目指向條目索引，條目索引的參照指向條目檔的標題。lint 載入時檢查每個指向都存在，每條規則都有檢查使用：

| 問題 | 表 |
|---|---|
| 條目寫在哪裡 | `rule-index` 是條目編號、段落與參照 |
| 怎麼判、怎麼回報 | `check-rules` 是規則，`check-levels` 是層級，`check-verdicts` 是判定值，`check-styles` 與 `check-style-levels` 是文風與它覆寫的層級，`check-thresholds` 是門檻，`check-patterns` 以正規式比對，`check-pairs` 找成對連接詞 |
| 這個寫法用不用 | `lex-avoid` 是不使用的寫法，`lex-locale` 是技術用語對照，`lex-english` 是英文詞的寫法，`lex-boundary` 是中文詞的邊界 |
| 版面怎麼寫、套用在哪些檔案 | `layout-profiles` 是路徑的 Wiki 版面與文風，`layout-formats` 是副檔名的格式，`layout-markdown` 是 markdown 寫法 |

## 共用寫法

全部檔案是 UTF-8 的 TSV，第一列是表頭，表頭與欄位數不符時 lint 以結束代碼 2 停止。各表共用下列寫法：

- 識別欄識別一列，同一個識別只寫一列。識別欄是第一欄，`check-style-levels` 是文風與規則兩欄，`lex-locale` 是英文與簡體中文兩欄。列依各欄的 Unicode 碼位排序，列序不承載規則。
- 一個儲存格有多個值時以頓號分隔，沒有值時寫 `-`，是非欄寫「是」或「否」。
- 層級、範圍、比對對象、格式與文風寫各自表內登記的值，值寫錯時 lint 以結束代碼 2 停止。
- 說明欄與改法欄是範本，以 `{名稱}` 標出 lint 代入的值。
- 例外欄列出含命中文字、但不算命中的整詞或命中文字本身，例如「落地頁」不算空話詞「落地」。
- 正規式欄的具名群組「命中」標出說明顯示的文字。
- markdown 寫法表的分隔行由上到下以頓號分隔，空行寫「空行」。
- 條目索引的參照寫成「檔案#標題」，檔案相對於 skill 目錄。
- 詞表的比對方式、成群門檻與術語的判定見 [design/engine](design/engine.md) 的「詞表比對」與「術語與重複的發現項目」，路徑樣式的比對見「路徑設定與文風」。

## 規則與層級

規則表的每一列是一條規則。判定欄是一個是非問題，答案「是」表示違規，沒有判定問題的規則寫 `-`，由 lint 直接判定。範圍欄決定規則套用在哪些檔案：「文字」套用在全部格式，「markdown」套用在 markdown 與 mdx，「Wiki 版面」只套用在 `layout-profiles.tsv` 判定為 Wiki 版面的檔案。

判定表定義判定值與依據的開頭，依據的開頭就是判定問題的答案。層級表定義每個層級的順位、要不要輸出、結束代碼、要不要填判定與對應的嚴重度，同一處的發現項目只留順位最高的一筆。

## 文風

文風是一組層級覆寫，依文件的寫作目的調整規則的鬆緊。`check-styles.tsv` 登記文風與說明，`check-style-levels.tsv` 寫每個文風把哪條規則改成哪個層級，規則寫「全部」時套用在全部規則，同一個文風內指名規則的列優先。一份文件套用哪些文風、層級怎麼計算，見 [design/engine](design/engine.md) 的「路徑設定與文風」與「層級的決定」。

## 檔案

各表的內容、讀取的模組與專案擴充方式依分組列出，各組的表依相依性由小到大排列。專案擴充方式寫「不可擴充」的表由本 skill 整批修改。其餘的表由專案放同表頭的 TSV，以 `--project` 傳入，lint 依表頭認出它擴充哪一張表。

### 條目

| 檔案 | 內容 | 讀取的模組 | 專案擴充方式 |
|---|---|---|---|
| `rule-index.tsv` | 每個條目所在的段落與參照，參照指向條目檔的標題。例如：ART-CORE-02 參照 `SKILL.md#核心原則` | `rules` 載入，`context` 使用 | 不可擴充 |

### 判定與回報

| 檔案 | 內容 | 讀取的模組 | 專案擴充方式 |
|---|---|---|---|
| `check-levels.tsv` | 層級的順位、輸出、結束代碼、判定與嚴重度。例如：提示會輸出，結束代碼是 0，判定選填 | `rules` 載入，`context`、`pipeline` 與 `output` 使用 | 不可擴充 |
| `check-verdicts.tsv` | 判定值與依據的開頭。例如：誤報的依據以「否」起頭 | `rules` 載入，`output` 使用 | 不可擴充 |
| `check-rules.tsv` | 規則的條目、預設層級、範圍、判定問題與改法。例如：「中文分號黏接」是 DOC-FMT-05 的警告，判定問題是「「；」連接的是兩個各自獨立的陳述嗎？」 | `rules` 載入，`context` 使用 | 不可擴充 |
| `check-styles.tsv` | 文風的名稱與用途。例如：參照文風用在欄位字典與對照表這類以表格為主的文件 | `rules` 載入，`context` 使用 | 附加 |
| `check-style-levels.tsv` | 各文風覆寫的規則層級。例如：參照文風關閉「中文分號」 | `rules` 載入，`context` 使用 | 附加，同文風、同規則時以專案的列為準 |
| `check-thresholds.tsv` | 各規則的門檻值。例如：中英夾雜的片語出現在 3 份以上的檔案時視為術語 | `rules` 載入，`pipeline` 使用 | 不可擴充 |
| `check-patterns.tsv` | 以正規式比對的規則。例如：「列舉省略」比對以「等」或 etc. 收尾的列舉 | `rules` 載入，`vocab` 使用 | 不可擴充 |
| `check-pairs.tsv` | 成對連接詞的開頭詞與接續詞。例如：「一來」之後要有「二來」 | `rules` 載入，`vocab` 使用 | 不可擴充 |

### 寫法

| 檔案 | 內容 | 讀取的模組 | 專案擴充方式 |
|---|---|---|---|
| `lex-boundary.tsv` | 排除命中用的中文邊界詞。例如：「同一」讓「同一來源」裡的「一來」不算命中 | `rules` 載入，`vocab` 使用 | 附加 |
| `lex-locale.tsv` | 技術用語在英文、簡體中文、大陸寫法與正體中文的對照。例如：大陸寫法 `人工智能` 對應正體中文「人工智慧」 | `rules` 載入，`vocab` 使用 | 不可擴充 |
| `lex-english.tsv` | 英文詞的標準寫法。例如：`GitHub` 是產品名稱 | `rules` 載入，`vocab` 與 `pipeline` 使用 | 附加，不分大小寫不得與其他詞表重複 |
| `lex-avoid.tsv` | 不使用的寫法與一對一的改用寫法。例如：「一定程度的」是疊加保留語 | `rules` 載入，`vocab` 使用 | 附加，不分大小寫不得與其他詞表重複 |

### 版面

| 檔案 | 內容 | 讀取的模組 | 專案擴充方式 |
|---|---|---|---|
| `layout-formats.tsv` | 副檔名對應的格式。例如：`.md` 依 markdown 解析，套用全部規則 | `rules` 載入，`pipeline` 使用 | 不可擴充 |
| `layout-markdown.tsv` | markdown 寫法的記號。例如：文風宣告的鍵是 `writing-style` | `rules` 載入，`parse`、`context` 與 `structure` 使用 | 不可擴充 |
| `layout-profiles.tsv` | 路徑樣式對應的 Wiki 版面與文風，skill 只提供預設列。例如：預設列 `**` 不採 Wiki 版面，文風是技術 | `rules` 載入，`context` 使用 | 整張取代 |

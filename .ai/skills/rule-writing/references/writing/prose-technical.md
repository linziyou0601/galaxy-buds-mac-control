# 技術文體

產品手冊、開發者文件、README、skill 與程式註解的讀者是來完成一件事的。他們要的是一次讀懂的直述句：做什麼、在哪裡做、做完會怎樣。本條目收錄技術文字最常出現的平均值痕跡。

## 否定補述與「不 X，只 Y」

### 偵測訊號

lint 的正規式表 `references/tables/check-patterns.tsv` 列出下列寫法：

- 否定補述：正面事實之後接「，不需要」「，不必」「，不是」「，而不是」「，無須」
- 二元句型：「不是 A，而是 B」「不只是 A，更是 B」
- 只與不並列：「只 A，不 B」「不 A，只 B」
- 缺席宣告：「本檔不處理」「本類別只負責」這類以本檔、本節開頭描述不做什麼的寫法

### 成因

模型寫完一個事實後，習慣再補一句它「不是什麼」，好像在預先回答讀者沒有問的問題。讀者讀到否定句時，得先想像那個被否定的選項，再把它丟掉，閱讀成本變高。範圍限制寫進條件本身，讀者就只需要記住一件事。缺席宣告讓讀者記住一份不存在的清單，改寫成實際做的事。

否定句只用在下列情況：

- 規則條文本身就是禁令。
- 否定的內容就是行為結果，例如「刪除後無法復原」。
- 省略這句否定，讀者會做出不可逆的錯誤操作。

### 改寫前

```text
選項來自所選的項目，不需要自己猜。
欄位只在儲存時檢查，不在輸入時檢查。
這個頁面不是用來新增資料的，而是用來查詢歷史紀錄。
本檔不處理權限，只負責欄位驗證。
```

### 改寫後

```text
選項取自目前選取的項目。
系統在按下儲存時檢查欄位。
這個頁面用來查詢歷史紀錄。
本檔驗證欄位。
```

## 名詞片段與敘述句

### 偵測訊號

說明欄、tooltip、表格說明格、欄位說明只寫名詞或名詞片段，例如「語言欄位」「顯示名稱設定」「狀態」。

### 成因

模型把說明欄當成標籤再寫一次。讀者打開 tooltip 或說明格，是想知道這個欄位做什麼、怎麼填。名詞片段只告訴讀者欄位叫什麼，這件事欄位名已經說了。名詞片段只用在標籤本身。

### 改寫前

```text
| 顯示名稱 | 各語系名稱 |
```

### 改寫後

```text
| 顯示名稱 | 選單在介面上顯示的名稱，每個語系各填一份，使用者切換語言後看到對應語系的名稱。 |
```

## 翻譯腔

### 偵測訊號

- 中文譯文：正規式表的「翻譯腔」（「進行……的動作」「對……進行」）、「區別語結尾」（「是必要的」「是可選的」「是唯一的」這類 `is required`、`is optional` 的直譯）與「被動結尾」（「會被驗證。」），以及「被……」「一個……的」「基於」「針對」「作為」堆疊、長串修飾語放在名詞前、句子照英文子句順序排列
- 英文譯文：照中文語序排列子句、重複主詞、`It is the place where...`、`Please kindly...`、把中文的四字詞逐字翻出

### 成因

模型翻譯時傾向逐句對應原文，保住原文語序。讀者看得出這段是翻過來的，因為句子不像以該語言直接寫成。譯文的目標是讓讀者讀到同樣的資訊，句構依目標語言重寫，術語與 UI 字串則與該語言的介面一致。

### 改寫前（中文）

```text
系統將會對使用者所輸入的資料進行一個驗證的動作。
這個欄位是必要的，資料送出前會被驗證。
```

### 改寫後（中文）

```text
系統會驗證使用者輸入的資料。
這個欄位必填，系統在送出前驗證資料。
```

### 改寫前（英文）

```text
In this page, it is the place where you can carry out the setting of the menu.
```

### 改寫後（英文）

```text
Use this page to configure the menu.
```

## 簡中與繁中用語

### 偵測訊號

簡中文字出現台灣用語，或繁中文字出現大陸用語。對照寫在技術用語對照表 `references/tables/lex-locale.tsv`，每列有英文、簡體中文、大陸寫法與正體中文，簡中文字依這張表反查台灣用語。大陸寫法是大陸用語以正體字寫成的樣子，lint 拿它比對繁中文字，依規則欄分成三種：

- 規則「簡繁用語（一對一）」的詞只有一種台灣說法，例如「默認」寫成「預設」，`lint.mjs --fix` 可以直接取代。
- 規則「簡繁用語（依語意）」的詞在台灣另有意思，例如「協議」在台灣指雙方的約定，通訊的 protocol 才寫成「協定」，讀過後依語意決定。
- 規則欄是「-」的列只作對照，例如「代碼」「登錄」「依賴」在台灣也是一般用法。

### 成因

簡繁轉換工具只換字形，詞彙仍是原來的地區用語。讀者一眼就看得出是轉出來的。產品介面已有 i18n 字串時，手冊用詞以該語系的 i18n 為準，兩邊說法才會一致。

### 改寫前

```text
在使用者资料页面建立新的设定后储存。
```

### 改寫後

```text
在用户信息页面创建新的设置后保存。
```

## 中英夾雜

### 偵測訊號

正規式表的「中英夾雜」：中文句子裡夾著兩個以上小寫英文單字組成的片語，例如「main agent 欄位由 main agent 填」。英文詞表 `references/tables/lex-english.tsv` 登記的片語，以及同一次檢查中出現在多份檔案的片語視為術語，不列出，檔案數門檻寫在 `references/tables/check-thresholds.tsv`。單一英文詞（例如 report、scope、spec）與連字的寫法（例如 whole-file）在判定時一併檢查。

### 成因

模型在中文句子裡保留英文片語，因為那是它思考時用的詞。散文中能用中文表達的英文片語，寫成中文。檔名、enum、yaml 欄位、phase 名，以及在 codebase 多檔一致使用的詞屬於技術術語，保留英文。判斷方式：這個詞在 codebase 多檔貫通使用，就是術語，只是描述用的片語，就翻譯。

### 改寫前

```text
main agent 依 disposition 選一動作，sub-agent 只執行，結果寫進 report。
```

### 改寫後

```text
主代理依 `disposition` 選定一個動作，子代理只負責執行，結果寫進報告。
```

## 公文腔

### 偵測訊號

規則「公文腔」，例如「必附」「均須」「予以」，以及以「於」「皆」「即」「須」「均」「之」取代「在」「都」「就」「要」「的」的書面寫法，後者在判定時一併檢查。

### 成因

模型模仿條文與公文的語感，用文言虛詞讓句子顯得正式。技術文件的讀者要的是一次讀懂，文言虛詞讓句子變短，卻讓讀者多一步轉換。條文本身的固定用語（例如規格的規範用語）依該規範，其餘寫成口語的書面中文。

### 改寫前

```text
blocker 必附 file:line，於交付自我檢查時皆須逐項覆核，即可結案。
```

### 改寫後

```text
blocker 要附上 file:line，交付前的自我檢查逐項覆核，全部通過後結案。
```

## 同一件事拆成多句

### 偵測訊號

- 同一件事的條件、動作或結果被句號切開，例如同一張單據的兩個狀態變化寫成兩句，兩句也算
- 一整段每句都很短
- 為了避開分號，把並列句也拆成獨立短句

### 成因

「兩個獨立陳述用句號分開」這條規則被套用過頭時，模型會把屬於同一件事的子句也切開，讀者得自己把這些短句拼回一件事。拆句以語意單位為準：同一件事寫在同一句，用逗號串接條件、動作與結果，彼此獨立的事才分句。標點的分工依 [format-markdown](format-markdown.md) 的「中文句讀」。為了製造張力而連續堆疊的宣告句，見 [prose-filler](prose-filler.md) 的「人造金句與斷奏式短句」。

### 改寫前

```text
點擊儲存。系統開始驗證。驗證通過。資料寫入資料庫。畫面顯示成功訊息。
```

### 改寫後

```text
點擊儲存後，系統先驗證欄位，通過後寫入資料庫並顯示成功訊息。
```

### 改寫前（說明段落）

```text
撰寫規格時依寫作姿態進入。判斷一句話屬於哪一層依層級職責。本目錄回答用詞是否合格。
```

### 改寫後（說明段落）

```text
撰寫規格時依寫作姿態進入，判斷一句話屬於哪一層依層級職責，本目錄回答用詞是否合格。
```

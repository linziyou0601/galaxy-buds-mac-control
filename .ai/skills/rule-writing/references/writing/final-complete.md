# 完整性

讀者依文件執行時，列出的內容就是全部內容。清單長度的計數（例如「分四個 namespace」）依 [prose-filler](prose-filler.md) 的「只描述清單長度的數字」。本檔的條目套用在全部格式。

## 列舉完整

表格、code block 與清單列出全部項目，每個 DDL 列出全部欄位。完整內容過長時，寫出總數並附代表性樣本與註記：「Showing N of M items. Full list available in {location}.」對清單完整性有疑慮時附註：「⚠️ 上述列表可能不完整。驗證方式：[glob pattern 或 search command]」。

### 判定候選

lint 以規則「列舉省略」列出以「等」、「etc.」、「and more」、「…」或「...」收尾的清單項與句子，以「例如」「諸如」帶出的舉例與表格列不列出。判定時確認列舉是否已完整：已完整時刪去收尾詞，未完整時補齊，內容過長時改寫成總數加樣本與註記。

## 完整路徑

列出受影響檔案時，逐一寫出自專案 root 起的完整路徑，引用 file、class 或 method 時同樣附完整路徑。

## 平行目錄

掃描範圍含平行目錄（語言版本、模組鏡像、src 與 test 對應）時，每個平行目錄都套用同樣的列表。

## 搜尋與掃描

執行掃描或列舉任務時，持續到可驗證完整為止，還有能提升完整性的 glob、grep 或讀檔，就執行它。搜尋沒有結果時，至少換一種方式再找（放寬 pattern、搜部分名稱、搜上層目錄、換工具），之後才標為「not found」。

## 重寫既有文件

重組或重寫既有文件時，新版保留原版全部資訊。刻意刪除的內容，在交付說明中寫出原因。

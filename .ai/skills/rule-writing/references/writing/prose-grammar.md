# 語言與語法

句構與詞彙層級的平均值痕跡。

## AI 高頻詞

### 偵測訊號

詞表 `references/tables/lex-avoid.tsv` 的規則「AI 高頻詞」，同一段落命中兩個以上時列出，門檻寫在 `references/tables/check-rules.tsv` 的成群門檻欄。

### 成因

這些詞在 AI 產生的文字中的出現頻率遠高於人寫的文字，而且常成群出現。單獨一個「此外」沒有問題，一段裡疊兩三個就是明顯訊號。

### 改寫前

```text
此外，這次重構至關重要，它彰顯了團隊對可維護性的重視，並為後續擴充奠定了寶貴的基礎。
```

### 改寫後

```text
這次重構把費用的計算集中到一個服務，新增費用類型時只需要改這個服務。
```

## 修飾語堆疊

### 偵測訊號

- 技術文字：規則「修飾語」，例如「其實」「基本上」「確實」「真正」「一般來說」「通常而言」
- 敘事段落：同一句疊兩個以上的程度副詞或狀態狀語，例如「一直非常」「習慣性地」「格外」「不斷」「始終」，由判定時檢查
- 敘事段落：「難過」「痛苦」「悲傷」這類情緒詞在鄰近句子接連出現，由判定時檢查

### 成因

模型為了讓句子聽起來自然、有情緒，習慣在動詞前補副詞，在名詞前補形容詞。這些詞在技術文字裡只增加字數，在敘事段落裡讓情緒詞一個接一個說出來，讀者被告知感受，卻沒有讀到引起感受的事。判斷方式：技術文字拿掉之後語意不變就刪，語意改變（例如「直接」表示跳過某個步驟）就保留。敘事段落刪掉重複與拿掉後畫面不變的修飾語，留下作者對事實的反應，只剩動作描寫會變成流水帳。

### 改寫前（技術文字）

```text
其實只要在右上角點一下儲存就可以了，系統基本上會直接幫你處理好驗證。
```

### 改寫後（技術文字）

```text
點右上角的儲存，系統會先驗證欄位，通過後寫入。
```

### 改寫前（敘事段落）

```text
那天晚上服務一直非常不穩定，我習慣性地反覆查看監控，內心格外焦慮，始終無法真正放鬆下來。
```

### 改寫過頭（只剩動作）

```text
那天晚上服務中斷了三次。我打開監控，關掉，又打開。凌晨兩點，我泡了一杯咖啡，放在桌上。
```

### 改寫後（敘事段落）

```text
那天晚上服務中斷了三次，我每隔幾分鐘就打開監控，明知道看了也不會比較快恢復。凌晨兩點泡的咖啡放到冷掉都沒喝，那時候我只想知道下一次什麼時候會來。
```

## 迴避「是」與「有」

### 偵測訊號

正規式表的「迴避是與有」：「作為……的核心」「扮演……角色」「代表著」「提供了一個」「具備了」。

### 成因

模型用迂迴結構取代「是」「有」，讓句子聽起來份量更重，讀者卻要多繞一圈。

### 改寫前

```text
稽核服務作為平台的稽核中心，具備記錄所有 API 呼叫的能力，扮演著追溯問題的關鍵角色。
```

### 改寫後

```text
稽核服務會記錄每一次 API 呼叫，排查問題時從這裡查起。
```

## 硬湊三項

### 偵測訊號

清單或並列形容詞每次都剛好三項，第三項明顯是為了湊數，由判定時檢查。

### 成因

三項讀起來有節奏感，模型因此偏好三項。清單的項數應該等於實際內容的數量。

### 改寫前

```text
新的匯入功能帶來效率、彈性與穩定。
```

### 改寫後

```text
新的匯入功能一次可以上傳整份 CSV，欄位對應可以自己調整。
```

## 名稱與實體不對應

### 偵測訊號

下列兩種都由判定時檢查：

- 同義詞輪換：同一個實體在鄰近句子輪流使用不同名稱，例如「服務」「模組」「元件」「系統」指同一個東西
- 同名異義：同一個名稱在同一份文件或同一組表裡指兩件事，例如「取值」同時當名詞（狀態的取值）與動詞（以鍵取值），表格的「性質」欄在兩張表各裝不同的分類

### 成因

模型為了避免重複用詞而換詞，讀者會以為是不同的東西。反方向是一個順手的名稱被拿去指第二件事，讀者以為是同一件事。技術文字中，一個實體全文使用一個名稱，一個名稱只指一個實體。

### 改寫前（同義詞輪換）

```text
排程服務會在指定時間觸發任務。這個模組也會記錄執行結果，元件失敗時系統會重試。
```

### 改寫後（同義詞輪換）

```text
排程服務會在指定時間觸發任務，記錄執行結果，並在任務失敗時重試。
```

### 改寫前（同名異義）

```text
狀態表列出每個狀態的取值。查詢時以訂單編號取值。
```

### 改寫後（同名異義）

```text
狀態表列出每個狀態的允許值。查詢時以訂單編號取得訂單。
```

## 成對連接詞只寫一半

### 偵測訊號

成對連接詞表 `references/tables/check-pairs.tsv`：同一個段落或同一份清單裡出現「首先」「一方面」「不但」「不僅」「一來」「其一」，之後卻沒有對應的「其次」「另一方面」「而且」「二來」「其二」。

### 成因

模型寫「首先」時已經預告了後面還有步驟，寫到後面卻忘了接上，讀者讀完還在等「其次」。開頭詞只在真的有後續時使用。只有一個步驟時刪去開頭詞，有後續時把後續寫出來。

### 改寫前

```text
首先檢查 Node 版本，確認環境變數都已設定。
```

### 改寫後

```text
首先檢查 Node 版本，接著確認環境變數都已設定。
```

## 虛假範圍

### 偵測訊號

「從 X 到 Y」，但 X 與 Y 不在同一個量尺上，由判定時檢查。

### 成因

「從……到……」聽起來涵蓋很廣，模型拿它來製造規模感。X 與 Y 不在同一量尺上時，這個範圍沒有意義，直接列出實際涵蓋的項目。

### 改寫前

```text
從資料庫設計到使用者體驗，從效能調校到團隊文化，這次改版全面提升了系統。
```

### 改寫後

```text
這次改版調整了訂單表的索引，並簡化了結帳頁的操作步驟。
```

## 無主語片段

### 偵測訊號

「不需要設定檔」「結果會自動保留」「可直接使用」這類省略動作者的片段，由判定時檢查。

### 成因

省略動作者後，讀者不知道是誰在做這件事：是使用者、系統，還是管理員。寫出動作者，句子就清楚了。

### 改寫前

```text
不需要設定檔。結果會自動保留。
```

### 改寫後

```text
系統會自動儲存結果，設定檔可以省略。
```

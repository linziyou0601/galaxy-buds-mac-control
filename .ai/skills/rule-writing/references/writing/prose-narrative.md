# 內容模式

敘事段落在內容層級灌水的方式：把普通事實吹成里程碑、用宣傳語取代描述、把觀點歸給不具名的權威。下列各節的偵測詞寫在詞表 `references/tables/lex-avoid.tsv`，以規則區分。

## 意義渲染

### 偵測訊號

規則「意義渲染」，例如「標誌著」「見證了」「彰顯其重要性」「奠定基礎」「關鍵轉折點」。

### 成因

模型習慣替任何細節補一句「這代表了更宏大的主題」，把普通事實寫成里程碑。

### 改寫前

```text
通知服務於 2026 年正式上線，標誌著平台通知機制演進史上的關鍵時刻，為未來的互動式通知奠定了堅實基礎。
```

### 改寫後

```text
通知服務於 2026 年上線，各模組透過它發送站內通知，通知可以附帶確認按鈕。
```

## 句尾補述式的偽分析

### 偵測訊號

規則「句尾偽分析」，例如句尾接「，反映了」「，展現出」「，有助於」。

### 成因

模型在句尾補一個分析性的短語，讓句子看起來有深度，補上的內容卻是空的。

### 改寫前

```text
列表頁改用分頁載入，反映了團隊對使用者體驗的重視，確保系統在大量資料下仍能流暢運作。
```

### 改寫後

```text
列表頁改用分頁載入，一萬筆紀錄也能在一秒內開啟。
```

## 宣傳語

### 偵測訊號

規則「宣傳語」，例如「強大的」「無縫」「一站式」。

### 成因

模型在介紹產品或功能時，很容易滑向行銷文案的語氣。文件讀者要的是功能做什麼、怎麼用。

### 改寫前

```text
身分驗證服務提供強大且無縫的一站式身分管理體驗，致力於打造極致安全的登入流程。
```

### 改寫後

```text
身分驗證服務負責平台的登入、多重要素驗證與使用者管理，支援密碼與第三方帳號登入。
```

## 模糊歸因

### 偵測訊號

規則「模糊歸因」，例如「業界普遍認為」「專家指出」「觀察者認為」。歸因實際只有一兩個來源卻寫成「許多來源」，由判定時檢查。

### 成因

模型把觀點歸給不具名的權威，讀者無從查證。寫出具體來源，或改成作者自己的判斷。

### 改寫前

```text
業界普遍認為，微服務架構能大幅提升系統的可維護性。
```

### 改寫後

```text
我們把通知拆成獨立服務後，修改通知邏輯只需要重新部署通知服務。
```

## 「挑戰與展望」段落

### 偵測訊號

規則「挑戰與展望」，例如「儘管面臨」「挑戰與展望」「未來展望」。

### 成因

模型在文章末尾內建一段公式化的「挑戰」收尾，假裝已經全面覆蓋議題。實際遇到的挑戰寫成具體事件與對應的處理。

### 改寫前

```text
儘管面臨效能與整合上的挑戰，憑藉團隊的努力與持續推進的計畫，專案仍將持續蓬勃發展。
```

### 改寫後

```text
大型檔案匯入在尖峰時段仍需要約十秒，下個版本會把解析移到背景工作。
```

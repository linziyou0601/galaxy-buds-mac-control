# 格式慣例

表格、code block、連結、連字號與中文句讀的寫法。code block 與連結的條目套用在 markdown 與 mdx，其餘條目套用在全部格式。

## 表格

比較、屬性與結構化資料使用表格，表格一律有表頭列。

## code block 的語言

code block 標明語言，例如 ` ```java `、` ```yaml `、` ```typescript `、` ```bash `，閱讀端才會套用語法高亮。lint 以規則「code block 沒有語言」檢查。

## 連結

連結寫成 `[顯示文字](path)`，讀者從文字就能判斷連結去向。lint 以規則「裸網址」列出沒有寫成連結的網址，以規則「連結文字是網址」列出顯示文字直接寫網址的連結。

## 加重語氣區塊

整句提醒使用專案既有的 callout 或 GitHub 提示區塊，寫法依 [project-policy](../project-policy.md)。區塊內的標題可以用粗體。

## 破折號

連字一律使用 ASCII 連字號 `-`，正文不寫 `—`、`–`，也不把 `--` 當破折號用。lint 以規則「破折號」檢查。

破折號是 AI 產生的文字最可靠的痕跡之一。敘事段落常用它模仿行銷文案的停頓節奏。替換順序：句號（另起一句）、逗號（緊密的插入語）、冒號（引出說明）、括號（插入語），或整句重組。命令列選項名稱（例如 `--fix`）寫在 code span 內，lint 不檢查 code span。

改寫前：

```text
這個設定主要給管理員使用——一般使用者看不到——但它會影響所有人的報表。
```

改寫後：

```text
這個設定只有管理員看得到，它會影響所有人的報表。
```

## 中文句讀

模型常用「；」把兩個沒有關係的陳述黏在一起，製造正式感。同樣的習慣也會表現成用換行取代句號，讓兩個獨立陳述看起來像條列。反方向的失誤是把同一件事拆成好幾個短句，見 [prose-technical](prose-technical.md) 的「同一件事拆成多句」。

中文散文的句讀依語意關係決定，逐句讀懂再下判斷。英文依英文標點習慣，semicolon 照英文語法使用，下列規則只適用於中文。lint 在表格以外的行找「；」，兩側分句都沒有逗號時以規則「中文分號黏接」列出，通常是兩個獨立陳述黏在一起。其他的「；」以規則「中文分號」列出，讀過後確認是否為結構對稱的並列句：

- 「，」串接同一件事的條件、動作、結果與補充，主題連貫的幾個短句也用逗號接成一句。
- 「。」用在主題轉換，或主詞不同、各自能獨立成立的陳述。一句串到四五個逗號時，在語意轉折處用句號斷開。
- 「；」只用在結構對稱、分句內通常已有逗號的並列句（例如「A 時 X，並 Y；B 時 Z，並 W」），以及表格 cell 內的並列項目與互為條件的因果。前後只是相關、結構不對稱時，用句號。
- 「、」用在並列的詞或短語。

改寫前：

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例；規格文件也進入補寫的高峰期。
```

改寫後：

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例。規格文件也進入補寫的高峰期。
```

改寫前（換行變體）：

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例
規格文件也進入補寫的高峰期
```

改寫後（換行變體）：

```text
規範文件補齊之後，AI 的輸出開始貼近團隊慣例。規格文件也進入補寫的高峰期。
```

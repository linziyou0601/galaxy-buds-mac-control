# 中文空話詞

中文技術圈有一批借自數學、工程或比喻的詞，以及截短後拼成的詞、自創的標籤，常被拿來取代具體的動作與結果。讀者讀完知道「有事發生」，卻不知道發生了什麼。改寫方向一致：寫出做了什麼決定、多了什麼能力、改了哪個流程，截短的詞寫回完整的詞，自創的標籤寫成它指的那件事。

## 偵測與判定

偵測詞寫在詞表 `references/tables/lex-avoid.tsv`，規則為「空話詞」「口頭單音節動詞」「截短的複合詞」。命中的詞換成具體的動作或結果後語意更清楚時，判為違規並改寫。下列各節的詞是各規則的代表，完整的詞以詞表為準。

## 討論的結論詞

```text
收斂
```

### 成因

原意是數值逐步逼近一個結果，常被套用在討論或意見結束的場合，取代「做了什麼決定」。

### 改寫前

```text
經過這次會議，大家對方案的看法逐漸收斂。
```

### 改寫後

```text
這次會議決定採用方案 B，方案 A 的快取分層設計暫緩。
```

## 能力轉移詞

```text
賦能
```

### 成因

把「讓某個角色多做成一件事」包裝成抽象的能力轉移，讀者看不出具體多做了什麼。

### 改寫前

```text
這次改版賦能了前端團隊，讓開發更有效率。
```

### 改寫後

```text
這次改版讓前端團隊自己調整欄位驗證規則，改完當天就能上線。
```

## 管道疏通詞

```text
打通
```

### 成因

暗示有人疏通了某段阻塞的管道，卻沒有說是哪一段流程、解決了什麼障礙。

### 改寫前

```text
這次整合打通了前後端的資料流。
```

### 改寫後

```text
這次整合讓前端直接讀後端的即時訂單狀態，畫面上的狀態與實際訂單同步。
```

## 著力點比喻

```text
抓手
```

### 成因

借用著力點的比喻代替說明從哪個環節切入，讀起來像決心宣言。

### 改寫前

```text
我們要把測試覆蓋率當作品質提升的抓手。
```

### 改寫後

```text
我們先把結算邏輯的測試覆蓋率補到八成，再擴大到其他模組。
```

## 回饋迴路詞

```text
閉環
```

### 成因

原意是控制系統的回饋迴路，常被拿來泛指有始有終的流程，卻沒有說明回饋實際怎麼運作。

### 改寫前

```text
這個功能讓使用者回饋形成閉環。
```

### 改寫後

```text
使用者在頁面上回報的異常會自動建立工單，指派給對應模組的負責人。
```

## 執行宣示詞

```text
落地
```

### 成因

描述計畫變成實際執行，堆疊使用時會取代「做了什麼」的具體描述，變成宣示。

### 改寫前

```text
這個構想已經在團隊裡落地。
```

### 改寫後

```text
這個構想已經寫進前端的元件型錄，團隊建新頁面時照著用。
```

## 拆分程度詞

```text
顆粒度
```

### 成因

這個詞描述拆分的精細程度，常被單獨拿來評論「不夠細」或「太粗」，卻沒有說該拆到哪個層級。

### 改寫前

```text
這份規格的顆粒度不太夠，需要再拆細一點。
```

### 改寫後

```text
這份規格目前寫到模組層級，需要補上每個欄位的驗證規則。
```

## 共識詞

```text
對齊
```

### 成因

原意是版面或座標排列一致，常被用來取代「確認了什麼共識」，讀起來像流程步驟，看不出實際結果。

### 改寫前

```text
這次會議先跟業務對齊需求。
```

### 改寫後

```text
這次會議確認業務要在付款成功當下寄出確認信。
```

## 競速比喻

```text
賽道
```

### 成因

借用競速比喻描述業務領域，放進技術文件通常只是空泛的分類詞。

### 改寫前

```text
這個模組要往推薦系統的賽道發展。
```

### 改寫後

```text
這個模組接下來會加入依瀏覽紀錄排序的推薦清單。
```

## 經驗留存詞

```text
沉澱
```

### 成因

借用化學「沉澱」的意象描述經驗留下來，卻沒有說留下的是什麼、放在哪裡。

### 改寫前

```text
這次專案的經驗會沉澱成團隊的知識資產。
```

### 改寫後

```text
這次專案遇到的問題整理成三份疑難排解文件，放在 wiki 的疑難排解區。
```

## 萬用改進詞

```text
完善
```

### 成因

萬用動詞，可以套在任何還能改進的事物上，卻沒有指出改進的項目與方向。

### 改寫前

```text
後續會持續完善這個功能。
```

### 改寫後

```text
下一版會在批次匯入時檢查欄位格式，錯誤訊息會標出出錯的列號。
```

## 祝福意象詞

```text
加持
```

### 成因

借用宗教語境的祝福意象，形容某項技術帶來的好處，內容語焉不詳。

### 改寫前

```text
有了 AI 加持，開發效率大幅提升。
```

### 改寫後

```text
AI 產生測試骨架後，開發者寫 spec 的時間大約少了三成。
```

## 口頭單音節動詞

```text
端 落 接 撈 掛 撞 追 吃 打
```

### 成因

借用端菜、掛物品這類日常動作的比喻代替實際操作，讀者得先猜出比喻指的是列出、寫入還是查詢，才讀得懂這句話。單音節動詞放在句尾也是同一種痕跡，例如「把結果存。」，正規式表 `references/tables/check-patterns.tsv` 的「單音節動詞結尾」列出這種寫法。

### 改寫前

```text
把到期項目端出來，結果落檔後掛上追蹤清單。
```

### 改寫後

```text
列出到期項目，結果寫入檔案後加進追蹤清單。
```

## 截短的複合詞

```text
重查 代寄 驗章 後接 切回 改綁 自檢 改檔 拆檔
```

### 成因

把雙音節動詞截成一個字，再拼上另一個字或詞，寫的人省了字，讀者得先還原被截掉的部分才讀得懂：「重查」是重新查詢，「代寄」是代為寄送，「驗章」是驗證簽章，「自檢」是自我檢查。教育部辭典收為詞條、意思不等於各字相加的詞，例如停用、歸還、取整，是完整的詞，照常使用。

### 改寫前

```text
回呼驗章失敗時切回草稿，使用者改綁帳號後重查。
```

### 改寫後

```text
回呼的簽章驗證失敗時，單據切換回草稿狀態，使用者重新綁定帳號，再查詢一次。
```

## 自創術語

```text
起手搜尋式 基底樣本 下完成宣稱
```

### 成因

模型替一個做法臨時取一個標籤，之後就用標籤指稱它，標籤沒有定義，也不是團隊既有的詞。讀者得先猜這個標籤指什麼，才讀得懂句子。自創術語不在任何詞表裡，lint 抓不到，由判定時檢查：一個詞在全文只有寫的人在用、也沒有定義時，寫成它指的那件事。需要反覆指稱的概念，先下定義再使用。

### 改寫前

```text
起手搜尋式是基底樣本，只跑起手樣本就下完成宣稱時拒收。
```

### 改寫後

```text
本節末的搜尋指令是基本範例，只跑基本範例就宣稱完成時，交付前的自我檢查不予通過。
```

# 填充與修辭腔

字詞層級的填充、過度限定，與修辭層級的假深度、宣告式開場、戲劇腔。下列各節的偵測詞寫在詞表 `references/tables/lex-avoid.tsv`，以規則區分，正規式寫在 `references/tables/check-patterns.tsv`。

## 填充短語

### 偵測訊號

規則「填充短語」。

### 成因

模型偏好迂迴的正式片語，字數變多，資訊量不變。

### 改寫對照

| 改寫前 | 改寫後 |
|---|---|
| 「為了達成這個目標」 | 「為了這件事」 |
| 「由於下雨這個事實」 | 「因為下雨」 |
| 「在這個時間點」 | 「現在」 |
| 「在你需要協助的情況下」 | 「如果你需要協助」 |
| 「系統具備處理的能力」 | 「系統可以處理」 |
| 「值得注意的是資料顯示」 | 「資料顯示」 |

## 只描述清單長度的數字

### 偵測訊號

正規式表的「清單長度數字」，例如「三大優勢」「分四個階段」「本檔列舉六種模式」，以及計數接冒號引出清單的「帶來三個改變：」。計數從「兩」起算，「一個」這類自然量詞與「第三個」這類序數不在比對範圍。

### 成因

模型習慣把項目數標出來，製造條理分明的感覺。這種數字只描述清單有多長，清單增減一項就變成錯的，直接列出內容。數字只用在有判定意義的地方：門檻（≥ 5、> 70%）、容量上限（context window 1M）、業務硬數字與自然量詞（「一份」「第一個」）。

### 改寫前

```text
這次改版帶來三大優勢：效能提升、介面簡化與維護成本降低。
```

### 改寫後

```text
這次改版縮短了查詢時間，設定頁少了兩個步驟，共用元件也集中到同一個函式庫。
```

## 疊加保留語

### 偵測訊號

規則「疊加保留語」。

### 成因

一句話前疊加多重保留語，讀起來像在迴避表態。

### 改寫前

```text
或許可以說這項政策有可能會對結果產生一定程度的潛在影響。
```

### 改寫後

```text
這項政策可能會影響結果。
```

## 通用樂觀結論

### 偵測訊號

規則「樂觀結論」。

### 成因

模型常用模糊而正向的句子收尾，聽起來像下了結論，內容卻是空的。

### 改寫前

```text
未來一片光明，令人期待的時代即將到來，團隊將持續朝卓越邁進。
```

### 改寫後

```text
下個 Sprint 會完成匯出流程的對接。
```

## 說服式權威腔

### 偵測訊號

規則「權威腔」，例如「真正的問題是」「從本質上來說」「問題的核心」。

### 成因

這類片語假裝要揭露某個深刻真相，接下來的句子通常只是把普通論點包裝得更隆重。

### 改寫前

```text
真正的問題是團隊能不能適應。從本質上來說，真正重要的是組織的準備程度。
```

### 改寫後

```text
問題在於團隊能不能適應，這多半取決於組織願不願意調整既有習慣。
```

## 宣告式開場

### 偵測訊號

規則「宣告式開場」，例如「讓我們深入探討」「以下是你需要知道的」「廢話不多說」。

### 成因

模型先宣告自己要做什麼，再開始做。這段後設評論拖慢節奏，讀起來像教學腳本。

### 改寫前

```text
讓我們深入探討 Next.js 的快取機制如何運作。以下是你需要知道的內容。
```

### 改寫後

```text
Next.js 在多個層級快取資料，包括請求記憶化、資料快取與路由快取。
```

## 破碎標題

### 偵測訊號

標題後第一句只重述標題，由判定時檢查。

### 成因

模型在標題後補一句只重述標題的暖場句，實際的內容才在後面。這句話不增加資訊。

### 改寫前

```text
## 效能

速度很重要。

頁面超過三秒沒有回應，使用者就會離開。
```

### 改寫後

```text
## 效能

頁面超過三秒沒有回應，使用者就會離開。
```

## 以差異為錨點的敘述

### 偵測訊號

規則「編輯過程用語」，例如「此次修改」「現在改」，以及英文的「previously」。規則「歷史敘事詞」，例如「原本」「更新為」。這幾個詞也會用來描述程式或資料先前的狀態，例如「原本的訂單數量」，讀過後確認這句是不是在敘述文件自己的修改過程。

### 成因

文件或註解寫成「這次改了什麼」，讀者得知道上一版長什麼樣子才看得懂。變更紀錄、release note 與遷移指南以外的文件，描述事物現在的樣子，編輯過程留在 commit message、PR 與變更紀錄。文件層級的編輯痕跡（diff 描述、版本增量註記、未完成標記）見 [final-current](final-current.md)。

### 改寫前

```text
這個函式是為了取代先前逐項遍歷所有項目、導致 O(n²) 效能問題的做法而新增的。
```

### 改寫後

```text
這個函式以雜湊表查詢，每次查詢的成本是 O(1)。
```

## 人造金句與斷奏式短句

### 偵測訊號

連續三句以上的短促宣告句，或每句都像能單獨截圖引用的金句，由判定時檢查。

### 成因

模型把每句話都寫得像能單獨截圖引用的金句，或疊一串短促的宣告句製造張力。單獨一句短句用來強調沒有問題，連續好幾句就顯得刻意。

### 改寫前

```text
接著新版排程上線了。沒有延遲。沒有遺漏。沒有人工介入。一切都變了。
```

### 改寫後

```text
新版排程上線後，任務都在預定時間觸發，這個月沒有出現需要人工補跑的情況。
```

## 格言公式

### 偵測訊號

規則「格言公式」，例如「是一面鏡子」「變成了一個陷阱」。「X 是 Y 的語言」這類句型由判定時檢查。

### 成因

模型把普通論點包裝成格言，聽起來深刻，精確度卻沒有增加。把格言拆回它想表達的具體主張。

### 改寫前

```text
對稱是信任的語言。當團隊忘記人的層面，效率就會變成一個陷阱。
```

### 改寫後

```text
對稱的版面讓使用者比較容易預測下一步。團隊過度優化流程時，有時會忽略人們實際使用的方式。
```

## 口語修辭開場

### 偵測訊號

規則「口語修辭開場」，例如「說真的」「老實說」「講白一點」，用作獨立的停頓再接一個普通論點。

### 成因

模型用假裝坦率的開場製造親密感，再丟出一個普通論點。坦率的人會直接說出那件事。

### 改寫前

```text
這值得那個價格嗎？說真的？要看你多常用它。
```

### 改寫後

```text
值不值得那個價格，要看使用頻率。
```

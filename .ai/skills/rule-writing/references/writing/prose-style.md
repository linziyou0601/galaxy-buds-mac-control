# 風格

符號與排列層級的痕跡。破折號、分號與粗體位置的判準與成因見 [writing-catalog](../writing-catalog.md) 的格式慣例與粗體使用，本條目收錄其餘的符號與排列。

## 粗體標籤條列

### 成因

模型把一段敘事拆成「**標籤**：說明」的條列，每項都是同樣的句型。欄位定義、設定項目這類結構化資料適合條列，敘事內容寫成段落。

### 改寫前

```text
- **使用者體驗**：透過新介面大幅改善使用者體驗。
- **效能**：透過最佳化演算法提升效能。
- **安全性**：透過端對端加密強化安全性。
```

### 改寫後

```text
這次更新換了新介面，查詢改用索引後快了一倍，傳輸也加上端對端加密。
```

## 表情符號

### 偵測訊號

正規式表 `references/tables/check-patterns.tsv` 的「開頭表情符號」與「表情符號」。前者比對標題與清單項開頭，後者比對表格以外的每個位置，同一個表情符號只列出一筆。箭頭與幾何符號不算表情符號，報告模板規定的狀態符號寫在例外欄。

### 成因

模型在標題或條列前加表情符號，製造活潑感。產品介面本身使用的圖示，以及報告模板規定的狀態符號（例如「✅」「🚧」），依模板保留，判定為誤報。

### 改寫前

```text
🚀 **啟動階段**：產品於第三季上市
💡 **關鍵洞見**：使用者偏好簡單
```

### 改寫後

```text
產品於第三季上市。使用者研究顯示，大家偏好步驟少的設計。
```

## 引號一致

### 判準

中文引號一律使用「」，英文引號依英文習慣使用 `"`，同一份文件不混用彎引號與直引號。正規式表的「彎引號」列出彎引號。

### 成因

聊天介面多半預設輸出彎引號，貼進文件後與既有的「」混在一起。

## 符號代替文字

### 偵測訊號

正規式表的「符號代替文字」：中文句子裡以 `!=`、`==`、`=`、`+`、`&&` 代替「不是」「是」「與」「且」。code span 內的程式寫法不檢查。

### 成因

模型把程式條件直接寫進中文句子，讀者要先把符號翻回語言才讀得懂這句話。程式條件寫在 code span 內，句子用文字陳述。

### 改寫前

```text
對每筆 action != 保留 的追蹤列，附上 spec + code 的 file:line。
```

### 改寫後

```text
對動作不是「保留」的每個追蹤列，附上規格與程式碼的 file:line。
```
